# 保存先、結果、対応範囲

## 保存先と保持するデータ

既定の配置です。`~` は実行ユーザーのホームフォルダです。

```text
~/.tkn/doc_summarizer/
├── config.yaml
├── data/
│   └── summaries/<year>/<date>_<title>_<profile>_<prompt-id-prefix>.md
├── prompts/
└── state/
    └── reports/<run-id>.json
```

| 保存するもの | 役割・保持する理由 |
| --- | --- |
| 要約ノート | 読み返す成果物。手動編集や確認状態を含むため、再生成前に必要な版を保持する |
| 元の文書 | 検証・再生成に必要。CLI は原本のコピーを保存しない |
| 設定とカスタムプロンプト | 保存先と生成条件を再現するために保持する |
| 実行レポート | 処理時刻、成功・失敗、生成条件の記録。削除するとその実行の記録を失う |

元文書と生成環境があれば再生成できますが、AI の利用が再び必要になり、同じ文章や手動編集は再現されません。外部プロセス・API・一時ファイルの管理は Bridge が担当します。ノートは保存先と同じフォルダに一時ファイルを準備してから置き換えます。

## ファイル名と既存ノートの識別

自動ファイル名の日付は元文書の `published` または `date`、ファイル名先頭の年月日、実行日の順に選びます。複数文書は先頭文書の日付を基準とし、文書の組の ID もファイル名に加えます。使えない文字は置換し、長いタイトルは短縮します。

既存ノートは `output_root` 配下で再帰検索します。単一文書は出典のパス・要約プロファイル・プロンプト ID、複数文書はモードと順序付き出典パスから作る `sourceSetId`・要約プロファイル・プロンプト ID で識別します。同じ保存先の中でノート名や場所を変えても識別情報があれば再利用できます。入力文書の移動や複数文書の並べ替えは識別情報を変えるため、同じノートとして扱われないことがあります。

ノート本文、Frontmatter の全項目、形式ごとの差異は [要約ノートの形式](note-format.md)にまとめています。

## 表示と実行レポート

進捗と診断は標準エラー出力、通常の成功結果は標準出力の JSON 1件です。`config list` は既定で1行ごとの `key=value`、`--json` 指定時は JSON です。`--help` と `--version` はテキストです。

| 表示・結果 | 意味・確認先 |
| --- | --- |
| `status: "planned"` | dry-run の計画。`path` と `details.planned_status` を確認 |
| `status: "created"` / `"updated"` | ノートを作成・更新。`path` を開く |
| `status: "unchanged"` | 有効な既存ノートを再利用 |
| `report_path` | JSON レポートの保存先。dry-run では `null` |
| `details.validated` | 保存済みノートの形式検証結果。意味や事実関係の正確さは保証しない |
| `[ERROR]` | エラー理由と、あれば `report=...` の保存先を確認 |

要約・統合の通常実行は再利用時もレポートを作ります。レポートの `status` は `success` / `failure`、ノートの作成・更新は `result.status`、失敗理由は `error` を確認します。レポート形式1.1の生成成功では、`result.details.generation_record` に Bridge の版、プロファイル名、生成条件・入力・スキーマのハッシュ、要求モデルと応答モデル、利用量・参考コストを記録します。Bridge の失敗時は `provider_error.code` と `provider_error.generation_record` に取得済み情報を記録します。未知の利用量・コストは `null` です。外部 CLI の版を取得しないため `provider_version` は `null` です。

Bridge の診断情報に入力文書・プロンプト・応答本文は保存しません。設定やプロファイルの読み込みなど、処理開始前の失敗、またはレポート保存自体の失敗ではレポートが残らないことがあります。一般の処理エラーでは標準出力に JSON が出ないため、終了コードと標準エラーも確認してください。`validate` の失敗は `valid: false` と `errors` を JSON で返します。

正常終了は `0`、設定・入力・生成・衝突・検証などの失敗は `1`、引数の誤りは `2` です。`--quiet` はエラーのみ、`--verbose` は詳細な診断を表示し、同時指定はできません。通常は `[INFO]`、成功時は `[SUCCESS]`、確認が必要な状態は `[WARNING]` を表示します。色対応端末では成功を緑、エラーを赤にし、リダイレクト、`NO_COLOR`、`TERM=dumb`、非対応端末では無色です。

## 書き込み範囲

| 操作 | AI の実行 | この CLI が保存するもの |
| --- | --- | --- |
| `summarize` / `synthesize` の新規作成・再生成 | あり | ノート、実行レポート |
| 同コマンドで `unchanged` | なし | 実行レポート |
| 同コマンドの `--dry-run` | なし | なし |
| `validate` / `config list` / `--help` / `--version` | なし | なし |
| `config init` | なし | 設定ファイル。`--force` による置換時はバックアップも作成 |
| `prompt init` | なし | 編集用プロンプト |

`--dry-run` は要約・統合に対応します。設定、入力、出力先の衝突、既存ノート、Bridge の接続設定と要求形式を検査します。書き込み、外部 CLI の起動・認証・通信はしません。既存ノートが有効なら `unchanged` を返し、通常実行で上書きが必要な場合は dry-run でも停止します。

## 対応範囲と制限

| 対象 | 対応する範囲 |
| --- | --- |
| 入力形式 | UTF-8 のテキストファイル。PDF・Word・画像の本文抽出はしない |
| Web 記事 | 保存済み Markdown。未保存ページの取得やクリップの完全性の検査はしない |
| 生成 AI | Bridge の Codex・Claude Code・GitHub Copilot・Antigravity・Ollama・Azure OpenAI 接続 |
| 長い文書 | 入力サイズの設定上限まで。分割して段階的に要約する機能はない |
| 処理単位 | 1回のコマンドで1ノート。フォルダ全体の一括処理や常駐監視はしない |

入力が空、UTF-8 として読めない、サイズ上限を超える場合は停止します。バイト数上限はモデルの入力長の保証ではありません。複数文書もまとめて AI に渡すため、モデル側の制約で失敗する場合があります。生成指示は出典に沿った記述を求め、入力に埋め込まれた指示を文書内容として扱わせますが、生成結果の意味や事実関係までは自動検証できません。元文書の不足を補完する機能はありません。
